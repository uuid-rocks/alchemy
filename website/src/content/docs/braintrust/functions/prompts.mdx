A **prompt** is a chat or completion template, with the model it runs on and that model's parameters. It lives in a project under a **slug**. Your app loads it by slug with the Braintrust SDK, or Braintrust runs it: as an eval's task, as a **scorer** that judges another answer, or as a tool for another prompt.

Every change to a prompt adds a **version**. Braintrust calls the model with the organization's [AI secret](/braintrust/access/secrets) for that provider.

## Declare a prompt

```typescript title="alchemy.run.ts"
const project = yield* Braintrust.Project("Support", {});
const summarize = yield* Braintrust.Prompt("Summarize", {
  projectId: project.projectId,
  slug: "summarize-ticket",
  promptData: {
    prompt: {
      type: "chat",
      messages: [
        { role: "system", content: "Summarize the ticket in one sentence." },
        { role: "user", content: "{{input}}" },
      ],
    },
    options: { model: "gpt-4o-mini", params: { temperature: 0 } },
  },
});
```

`{{input}}` is filled in from each call's input. `promptData` is written as a whole, so a field you remove is gone from the next version.

Alchemy writes a new version only when the prompt you declare differs from the one deployed, so redeploying an unchanged prompt keeps its version. `summarize.version` is the current one: pass it with the project and slug to the Braintrust SDK's `loadPrompt` to load exactly what you deployed.

Changing the slug keeps the prompt and adds a version. Moving it to another project replaces it, and every version of the old one is deleted.

To have `staging` or `production` serve each new version, list them in `environments`. See [Environments](/braintrust/functions/environments#serve-a-prompt-from-an-environment).

## Judge answers with an LLM

A prompt with `functionType: "scorer"` is an **LLM-as-a-judge** scorer. Its `parser` turns the model's answer into a score:

```typescript title="alchemy.run.ts"
const politeness = yield* Braintrust.Prompt("Politeness", {
  projectId: project.projectId,
  slug: "politeness",
  functionType: "scorer",
  promptData: {
    prompt: {
      type: "chat",
      messages: [{ role: "user", content: "Is this reply polite? {{output}} Answer Yes or No." }],
    },
    options: { model: "gpt-4o-mini" },
    parser: { type: "llm_classifier", use_cot: true, choice_scores: { Yes: 1, No: 0 } },
  },
});
```

`use_cot` lets the model reason before it picks a choice, and `choice_scores` maps each choice to a score. Scorers written as code are in [Functions and scorers](/braintrust/functions/functions).

## Let a prompt call tools

`tool_functions` lists the functions the model may call, and `mcp` lists [MCP servers](/braintrust/functions/mcp-servers) whose tools it may use. A tool is a function with `functionType: "tool"`; see [Functions and scorers](/braintrust/functions/functions#tools-for-prompts).

## Call a model through the proxy

Braintrust's **AI proxy** takes OpenAI's request format for any provider, picks the provider from `model`, and calls it with the organization's AI secret. A Worker can call models with that key without ever holding it.

`ProxyChatCompletions` binds one AI secret: the host's own service token gets `read` on it. The proxy uses any AI secret that token can read, and picks among them by `model`, so bind one secret per provider. A host bound to two secrets for the same provider can't choose which one a call uses.

```typescript title="src/openai.ts"
import * as Braintrust from "@alchemy.run/braintrust";
import * as Config from "effect/Config";

export const OpenAI = Braintrust.AiSecret("OpenAI", {
  name: "OPENAI_API_KEY",
  type: "openai",
  secret: Config.Redacted("OPENAI_API_KEY"),
});
```

Pass the `Config` itself, without `yield*`. The deploy reads it when it stores the secret. A `Config` read with `yield*` inside the Worker's setup is bound into the Worker as a variable, which would hand it the key.

```typescript title="src/api.ts"
import * as Braintrust from "@alchemy.run/braintrust";
import * as Cloudflare from "@alchemy.run/cloudflare";
import * as Effect from "effect/Effect";
import { HttpServerRequest } from "effect/http/HttpServerRequest";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
import { OpenAI } from "./openai.ts";

export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const chat = yield* Braintrust.ProxyChatCompletions(OpenAI);
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const question = yield* request.text;
        const completion = yield* chat({
          model: "gpt-4o-mini",
          messages: [{ role: "user", content: question }],
        });
        return yield* HttpServerResponse.json(completion);
      }).pipe(Effect.orDie),
    };
  }).pipe(Effect.provide(Braintrust.ProxyChatCompletionsHttp)),
) {}
```

`ProxyCompletions`, `ProxyEmbeddings` and `ProxyAuto` bind the same way, for completions, embeddings, and either one picked by model. `ProxyRequest` sends any other OpenAI API request, by its path. None of them stream: responses come back whole.

To run the prompt itself from your app, rather than a model, bind it with `InvokeFunction`. See [Functions and scorers](/braintrust/functions/functions#run-a-function-from-your-app).

## Use a prompt you didn't create

```typescript title="alchemy.run.ts"
const existing = Braintrust.Project.lookup({ name: "My Project" });
const greeting = Braintrust.Prompt.lookup({ projectId: existing.projectId, slug: "greeting" });
```

A prompt's `tags` are yours to set, so Alchemy has no label to recognize its own prompts by. Declaring a prompt under a `slug` that already exists is refused unless you adopt it. `lookup` only reads the prompt, so it needs no adoption.
