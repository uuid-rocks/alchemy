A project's **logs** are its production traces. Each trace is a tree of **spans**, one per step your app took: the request, a model call, a tool call. Each span has an `input`, an `output`, `metadata` you filter on, and the `scores` that reviewers and online scorers add later.

Writing logs needs a key with `update` on the project's logs. A Worker gets its own through a binding. A browser, or any client you can't trust with an API key, gets an **ingest key** that can only write one project's logs.

## Log from a Worker

`InsertProjectLogs` binds a project's logs to a Worker or Function. The host gets its own service account and token, with `update` on this project's logs only, passed in as `BRAINTRUST_API_KEY`. Destroying the host cancels the token. Creating it needs a deployer signed in with a service token; see [Setup](/braintrust/setup#choose-a-key).

```typescript title="src/evals.ts"
import * as Braintrust from "@alchemy.run/braintrust";

export const Support = Braintrust.Project("Support", {});
```

```typescript title="src/api.ts"
import * as Braintrust from "@alchemy.run/braintrust";
import * as Cloudflare from "@alchemy.run/cloudflare";
import * as Effect from "effect/Effect";
import { HttpServerRequest } from "effect/http/HttpServerRequest";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
import { Support } from "./evals.ts";

export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const log = yield* Braintrust.InsertProjectLogs(yield* Support);
    return {
      fetch: Effect.gen(function* () {
        const question = yield* (yield* HttpServerRequest).text;
        const answer = "Reset it from Settings → Password.";
        const { row_ids } = yield* log({
          events: [{ input: question, output: answer, metadata: { model: "gpt-4o-mini" } }],
        });
        return yield* HttpServerResponse.json({ answer, logId: row_ids[0] });
      }).pipe(Effect.orDie),
    };
  }).pipe(Effect.provide(Braintrust.InsertProjectLogsHttp)),
) {}
```

`row_ids` are the ids of the logged rows. Hand one back to the client, and it can rate the answer later; see [Human review](/braintrust/observability/review#feedback-from-your-users).

## Read logs back

`FetchProjectLogs` grants `read` instead, and its client pages through the logs with `fetch({ limit, cursor })`. `ReadWriteProjectLogs` grants both, with `fetch`, `insert` and `feedback` on one client:

```typescript
const logs = yield* Braintrust.ReadWriteProjectLogs(yield* Support);
const { events, cursor } = yield* logs.fetch({ limit: 100 });
```

## Ingest keys for browsers

An **ingest key** is a publishable credential: it can only write logs, to one project. It never expires, and lasts until it is deleted:

```typescript title="alchemy.run.ts"
const project = yield* Braintrust.Project("Support", {});
const key = yield* Braintrust.IngestKey("BrowserLogs", { projectId: project.projectId });
```

Braintrust returns the key inside a configuration URL, `key.url`, which stays `Redacted`. Pass it to the client that sends logs.

An ingest key can't be changed: a new `name` or `projectId` deletes the key and creates one with a different URL. Braintrust may keep accepting a deleted key for a while, until its caches expire.
