A **project** holds everything about one AI feature or app: its production logs, datasets, experiments, prompts, functions, scores and views. Most of what you declare in Braintrust takes a `projectId`.

Deleting a project deletes everything in it, logs and experiment results included.

## Create a project

```typescript title="alchemy.run.ts"
const project = yield* Braintrust.Project("Support", {
  description: "Evals and logs for the support bot",
});
```

Without a `name`, Alchemy generates one from the Stack, the stage and the logical ID, so every stage gets its own project and a pull request's evals never mix with production's. `project.projectId` is what everything inside it takes.

Give it a fixed `name` when people find it in the Braintrust UI by name. Renaming a project keeps its id and everything in it:

```typescript title="alchemy.run.ts"
const bot = yield* Braintrust.Project("Bot", { name: "support-bot" });
```

Braintrust projects carry no tags, so Alchemy recognizes a project by its name. One that already exists under a fixed name is refused unless you adopt it. See [Adopting resources](/cli/adopting-resources).

## Compare experiments your way

Braintrust lines up two experiments' rows by `input`. When inputs vary between runs, compare on a stable field instead, like a case id in each record's metadata:

```typescript title="alchemy.run.ts"
const triage = yield* Braintrust.Project("Triage", {
  settings: {
    comparisonKey: "metadata.case_id",
    blindReviews: true,
  },
});
```

`blindReviews` hides other reviewers' scores until a reviewer has submitted their own. `baselineExperimentId` sets the experiment every run is compared with by default. Once you declare `settings`, Alchemy manages all of them: a setting you leave out goes back to Braintrust's default, even one turned on in the UI. Without `settings`, Alchemy leaves the project's settings alone.

Every project setting is declared the same way, including which fields identify your users and sessions, where Pattern alerts go, and the default preprocessor:

```typescript title="alchemy.run.ts"
const support = yield* Braintrust.Project("Support", {
  settings: {
    userIdFields: [["metadata", "customer_id"]],
    sessionIdFields: [["metadata", "conversation_id"]],
    patternAlertDestinations: [{ type: "webhook", url: "https://example.com/alerts" }],
    defaultPreprocessor: { type: "global", name: "thread" },
  },
});
```

## Share access across projects

A **project group** is a set of projects that share access. An ACL on the group applies to every project in it, and to projects added later.

Each project joins groups through its own `projectGroupIds`:

```typescript title="alchemy.run.ts"
const team = yield* Braintrust.ProjectGroup("SupportTeam", {
  description: "Projects the support team works on",
});
const escalations = yield* Braintrust.Project("Escalations", { projectGroupIds: [team.projectGroupId] });
const refunds = yield* Braintrust.Project("Refunds", { projectGroupIds: [team.projectGroupId] });
```

Then grant on the group's projects with the `project_group_projects` object type:

```typescript title="alchemy.run.ts"
const readers = yield* Braintrust.Group("SupportReaders", {});
yield* Braintrust.Acl("ReadSupportProjects", {
  objectType: "project_group_projects",
  objectId: team.projectGroupId,
  groupId: readers.groupId,
  permission: "read",
});
```

Once a project lists `projectGroupIds`, it leaves any group it doesn't list, and removing the prop later takes it out of every group. Alchemy doesn't touch the groups of a project that never listed them. See [Roles, groups and ACLs](/braintrust/access/access-control).

## Use a project you didn't create

`lookup` reads a project made in the UI, or by another Stack, by name. Alchemy never changes or deletes it, and you can add to it:

```typescript title="alchemy.run.ts"
const existing = Braintrust.Project.lookup({ name: "My Project" });
const golden = yield* Braintrust.Dataset("Golden", { projectId: existing.projectId });
```
